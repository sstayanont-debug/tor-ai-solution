# TOR AI Solution — End-to-End Project Lifecycle Copilot

แอปพลิเคชัน AI สำหรับบริษัทที่ยื่นประมูลโครงการภาครัฐ/เอกชน ครอบคลุมวงจรโครงการทั้งหมด:
**วิเคราะห์ TOR → ตัดสินใจ Bid/No-Bid → งานขาย (BOM/Costing, คู่แข่ง, Proposal) → งานจัดซื้อ (RFQ/Vendor) → งานสัญญา (Redlining, Obligation Tracker)**

ดูสถาปัตยกรรมฐานข้อมูลและ workflow แบบละเอียดได้ที่ [`DESIGN_SCHEMA.md`](./DESIGN_SCHEMA.md)

## โมดูลหลัก

### 🚦 ขั้นตอนแรก: วิเคราะห์ TOR + ตัดสินใจ Bid/No-Bid (ประตูก่อนลงทุนแรง)
1. **วิเคราะห์ TOR** — สกัดขอบเขตงาน งบประมาณ กำหนดยื่น คุณสมบัติผู้ยื่น เกณฑ์ให้คะแนน และความเสี่ยงจากตัวเอกสาร
2. **ประเมินความเสี่ยง** — ให้คะแนนความเสี่ยง 5 มิติ (การเงิน เทคนิค ระยะเวลา การแข่งขัน กฎหมาย) พร้อมข้อเสนอแนะบรรเทาความเสี่ยง
3. **ประเมินโอกาสชนะงาน (Bid/No-Bid)** — ให้ % โอกาสชนะพร้อมเหตุผล จุดแข็ง/จุดอ่อน และคำแนะนำ **ควรเข้าประมูล / ควรพิจารณาอย่างระมัดระวัง / ไม่ควรเข้าประมูล**
   ระบบจะแสดงป้ายคำแนะนำนี้เด่นชัดในหน้าโครงการ เพื่อกันไม่ให้ทีมขายเสียเวลาทำงานต่อในโครงการที่ไม่คุ้ม

### 💼 งานขายโครงการ (Sales & Pipeline)
4. **BOM / Costing** — AI ร่าง solution architecture ตอบโจทย์ TOR แล้วแตกเป็นรายการ BOM พร้อมประเมินต้นทุน/ราคาขาย คำนวณ margin อัตโนมัติ แก้ไขราคาเองได้
5. **Competitor Intelligence** — วางข้อมูลคู่แข่งที่ทราบ ให้ AI แนะนำจุดข่ม (differentiator) เทียบกับคู่แข่งรายนั้น
6. **สนับสนุนการขาย** — สร้างบทสรุปผู้บริหาร, value proposition, key message, การรับมือข้อโต้แย้ง สำหรับทีมขายใช้ยื่นข้อเสนอ

### 🧾 งานจัดซื้อโครงการ (Procurement) — ใช้หลังชนะงาน
7. **RFQ จาก BOM** — สร้างใบขอราคาจากรายการ BOM อัตโนมัติ วาง/อัปโหลดใบเสนอราคาที่ได้รับจาก vendor ให้ AI สกัดราคา/ระยะเวลาส่งมอบ/เงื่อนไข SLA และเทียบสเปคให้ในตารางเดียว พร้อมประเมินความเสี่ยงส่งมอบล่าช้า

### ⚖️ งานสัญญาโครงการ (Contract Lifecycle) — ใช้หลังชนะงาน
8. **Contract Redlining** — AI สแกนร่างสัญญา หาข้อเสี่ยง/เสียเปรียบ (ค่าปรับเกินมาตรฐาน, เงื่อนไข IP ไม่เป็นธรรม ฯลฯ) พร้อมข้อเสนอแย้งเบื้องต้น (ไม่ใช่คำแนะนำทางกฎหมายที่สมบูรณ์)
9. **Obligation Tracker** — ดึงข้อผูกมัดทั้งหมดจากสัญญา (ไม่ใช่แค่ deliverable แต่รวม reporting/ประกัน/กฎหมาย) มาติดตามสถานะ
10. **Milestone Tracker** — แตกงานเป็น milestone/deliverable อัตโนมัติจาก TOR และติดตามความคืบหน้า

### 📬 Inbox TOR Watcher (หางานเชิงรุกจากอีเมล)
14. **สแกนอีเมลหา TOR/RFP** — เชื่อมต่อ Gmail ของทีมขาย ค้นหาอีเมลที่มีไฟล์แนบและตรงคีย์เวิร์ด (TOR, RFP, เชิญยื่นข้อเสนอ ฯลฯ) ให้ผู้ใช้ตรวจสอบและกด "นำเข้าเป็นโครงการ" — AI จะวิเคราะห์ TOR ให้ทันที เข้าสู่ pipeline เดียวกับการอัปโหลดเอง ดูหัวข้อ **Inbox TOR Watcher** ด้านล่างสำหรับวิธีตั้งค่า

### 🏛️ e-GP Market Intelligence (ข้อมูลตลาดจากภาครัฐ)
15. **ค้นหาสัญญาที่ประมูลเสร็จแล้ว** — ดึงข้อมูลจาก Open Data ทางการของกรมบัญชีกลาง (govspending.data.go.th) ค้นด้วยคีย์เวิร์ด/เลขผู้เสียภาษีคู่แข่ง/หน่วยงาน/ปี/ช่วงงบประมาณ แล้วบันทึกเป็นข้อมูลคู่แข่งในโครงการที่เลือกได้ทันที (เชื่อมกับแท็บ "คู่แข่ง" ที่มีอยู่แล้ว) ดูหัวข้อ **e-GP Market Intelligence** ด้านล่างสำหรับวิธีตั้งค่า

### 🔐 ระบบ Login และสิทธิ์ผู้ใช้ (มี multi-user + RBAC ในตัวแล้ว)
11. **Login** — ผู้ใช้ทุกคนต้อง login ด้วยอีเมล/รหัสผ่านก่อนใช้งานทุกหน้า
12. **บทบาท (Role) ตามส่วนงาน** — admin / sales / procurement / legal แต่ละคนเห็นเฉพาะหน้าที่เกี่ยวข้องกับหน้าที่ตัวเอง
13. **จัดการผู้ใช้ (Admin only)** — สร้าง/ระงับผู้ใช้ กำหนด role และส่วนงาน เปลี่ยนรหัสผ่าน และดู audit log ว่าใครทำอะไรเมื่อไหร่

ทุกขั้นตอนใช้ Claude (Anthropic API, tool-use แบบบังคับ JSON schema) วิเคราะห์จริง ไม่ใช่ข้อมูลจำลอง ข้อมูลทั้งหมดถูกเก็บไว้ในเครื่องที่รันแอป (SQLite local file) ไม่ส่งขึ้น cloud ใดๆ นอกจาก Anthropic API ตอนเรียกวิเคราะห์

**ข้อจำกัดปัจจุบัน:** e-GP ดึงได้เฉพาะสัญญาที่ประมูลเสร็จแล้ว (ไม่มี live feed ประกาศที่เปิดอยู่ตอนนี้จาก API ทางการ), ไม่ส่งอีเมล RFQ หา vendor อัตโนมัติ, และไม่ sync กับ Jira/Trello/Asana/CRM/ERP — ผู้ใช้ป้อน/วางข้อมูลที่เกี่ยวข้องเอง ดูรายละเอียดใน `DESIGN_SCHEMA.md` หัวข้อ 8-10

## ติดตั้ง

ต้องมี Python 3.9+

```bash
cd tor-ai-solution
pip install -r requirements.txt
```

## ตั้งค่า API Key

1. สมัคร/รับ API key จาก https://console.anthropic.com
2. คัดลอกไฟล์ `.env.example` เป็น `.env`
3. ใส่ API key ของคุณในไฟล์ `.env`:

```
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## รันแอป

```bash
streamlit run app.py
```

จากนั้นเปิดเบราว์เซอร์ตามลิงก์ที่ปรากฏ (ปกติคือ http://localhost:8501)

## เข้าสู่ระบบครั้งแรก (Login)

ระบบสร้างบัญชี **ผู้ดูแลระบบ (admin)** ให้อัตโนมัติในการรันครั้งแรก (เมื่อยังไม่มี user ใดเลยในฐานข้อมูล) โดยใช้ค่าจาก `.env`:

```
DEFAULT_ADMIN_EMAIL=admin@company.local
DEFAULT_ADMIN_PASSWORD=ChangeMe123!
```

**ขั้นตอนแนะนำ:**
1. ตั้งค่า `DEFAULT_ADMIN_EMAIL`/`DEFAULT_ADMIN_PASSWORD` เป็นของจริงใน `.env` ก่อนรันแอปครั้งแรก (หรือใช้ค่าเริ่มต้นแล้วไปเปลี่ยนทีหลังก็ได้)
2. รันแอป แล้ว login ด้วยบัญชีนี้
3. ไปที่หน้า **จัดการผู้ใช้** (เห็นเฉพาะ admin) → แท็บ **เปลี่ยนรหัสผ่าน** เพื่อเปลี่ยนรหัสผ่าน admin เป็นของจริง
4. ไปที่แท็บ **ส่วนงาน** สร้างส่วนงานตามองค์กรจริง (เช่น ฝ่ายขาย, ฝ่ายจัดซื้อ, ฝ่ายกฎหมาย)
5. ไปที่แท็บ **ผู้ใช้งาน** สร้างบัญชีให้พนักงานแต่ละคน กำหนด role และส่วนงานให้ตรงหน้าที่

### ตาราง Role ↔ หน้าที่เข้าถึงได้

| หน้า | admin | sales | procurement | legal |

| ตรวจสัญญา (Redlining) | ✅ | ❌ | ❌ | ✅ |
| TOR จากอีเมล (Inbox Watcher) | ✅ | ✅ | ❌ | ❌ |
| e-GP Market Intelligence | ✅ | ✅ | ❌ | ❌ |

admin เห็นและแก้ไขได้ทุกหน้าเสมอ ถ้าต้องการเพิ่ม role ใหม่หรือปรับสิทธิ์การเข้าถึง แก้ที่ `auth.ROLE_LABELS` และค่าที่ส่งให้ `auth.require_role([...])` บนสุดของแต่ละหน้าใน `pages/*.py`

## Inbox TOR Watcher (ตั้งค่า Gmail ให้สแกนหา TOR อัตโนมัติ)

ฟีเจอร์นี้ไม่บังคับ — ข้ามได้ถ้ายังไม่ต้องการ ใช้เมื่อพร้อมต่อ Gmail ของทีมขายเพื่อหางานเชิงรุก

**คำแนะนำสำคัญ:** ใช้อีเมลกลางของทีม (เช่น `sales@company.com`) ไม่ใช่อีเมลส่วนตัวพนักงาน เพราะระบบจะสแกนเฉพาะอินบ็อกซ์ของบัญชีที่ authorize เท่านั้น และควรให้สิทธิ์แบบ **read-only** (ระบบขอสิทธิ์นี้อยู่แล้วโดยค่าเริ่มต้น ไม่ได้ขอสิทธิ์ลบ/ส่งอีเมล)

**ขั้นตอนตั้งค่า:**
1. ไปที่ [Google Cloud Console](https://console.cloud.google.com/) สร้างโปรเจกต์ใหม่ (หรือใช้ของเดิม)
2. เปิดใช้งาน **Gmail API** ที่เมนู APIs & Services → Library
3. ไปที่ APIs & Services → OAuth consent screen ตั้งค่าเบื้องต้น (เลือก External ถ้าไม่ใช่ Google Workspace องค์กร, เพิ่ม scope `gmail.readonly`, เพิ่มอีเมลที่จะใช้ authorize เป็น test user ถ้ายังอยู่ใน testing mode)
4. ไปที่ Credentials → Create Credentials → OAuth client ID → เลือกประเภท **Desktop app**
5. ดาวน์โหลดไฟล์ JSON ที่ได้ เปลี่ยนชื่อเป็น `credentials.json` แล้ววางไว้ที่ root ของโปรเจกต์ (โฟลเดอร์เดียวกับ `app.py`)
6. รันแอป ไปที่หน้า **TOR จากอีเมล** กดปุ่ม **เชื่อมต่อ Gmail** — เบราว์เซอร์จะเปิดหน้าล็อกอิน Google ให้ authorize ด้วยบัญชีที่ต้องการสแกน
7. หลัง authorize ระบบจะเก็บ token ไว้ที่ `data/gmail_token.json` ใช้ซ้ำได้โดยไม่ต้อง login ใหม่ (จนกว่าจะยกเลิกการเชื่อมต่อ หรือ token หมดอายุ)

**การใช้งาน:** ตั้งคีย์เวิร์ดและจำนวนวันย้อนหลัง → กด "สแกนอีเมลตอนนี้" → ระบบแสดงอีเมลที่เข้าเงื่อนไข (มีไฟล์แนบ + ตรงคีย์เวิร์ด) → เลือก "นำเข้าเป็นโครงการ" รายที่สนใจ ระบบจะดึงไฟล์แนบ (PDF/DOCX) มาให้ AI วิเคราะห์ TOR ทันที เข้าสู่ pipeline เดียวกับการอัปโหลดเอง

**ข้อควรรู้:**
- ไฟล์ `credentials.json` และ `data/gmail_token.json` เป็นความลับ ห้ามแชร์/commit เข้า git (มี `.gitignore` กันไว้ให้แล้ว)
- นี่คือการดึงอีเมลที่ **ส่งเข้ามาถึงบริษัทเองแล้ว** ไม่ใช่การไปสอดส่อง/ดึงข้อมูลจากบริษัทอื่น จึงไม่มีประเด็นด้านกฎหมาย/ToS แบบเดียวกับการ scrape เว็บภายนอก
- ถ้าต้องการให้สแกนอัตโนมัติเป็นประจำ (ไม่ต้องกดเองทุกวัน) ต้องตั้ง cron job หรือ Task Scheduler ของ OS ให้รันสคริปต์ที่เรียกฟังก์ชันใน `email_watcher.py` เป็นระยะ — เวอร์ชันนี้เป็นแบบกดสแกนเองผ่านหน้าเว็บ

## e-GP Market Intelligence (ตั้งค่า API key ข้อมูลจัดซื้อจัดจ้างภาครัฐ)

ไม่บังคับ — ข้ามได้ถ้ายังไม่ต้องการ ใช้ Open Data ทางการของกรมบัญชีกลาง ไม่ใช่การ scrape เว็บ

**ขั้นตอนตั้งค่า:**
1. ไปที่ https://opend.data.go.th/register_api สมัครขอ API key ฟรี (ใช้อีเมลองค์กรสมัคร)
2. เมื่อได้ API key แล้ว ใส่ในไฟล์ `.env`:
   ```
   EGP_API_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
3. รันแอป ไปที่หน้า **e-GP Market Intelligence** ค้นหาด้วยคีย์เวิร์ด/ชื่อ-เลขผู้เสียภาษีคู่แข่ง/หน่วยงาน/ปี

**ข้อควรรู้:**
- ข้อมูลที่ได้คือ**สัญญาที่ประมูลเสร็จแล้ว** (ใครชนะ ราคาเท่าไหร่) ไม่ใช่ประกาศที่เปิดรับอยู่ตอนนี้ — เหมาะสำหรับวิจัยคู่แข่ง/เบนช์มาร์กราคา ไม่ใช่หางานใหม่
- ชื่อ field ของ "ผู้ชนะ" และ "ราคา" ใน API ยังไม่ได้ยืนยัน 100% จากเอกสารสาธารณะที่หาได้ตอนพัฒนา ระบบพยายามจับคู่ field ที่เป็นไปได้หลายชื่อให้อัตโนมัติ แต่ **ควรตรวจสอบ "ข้อมูลดิบ (Raw JSON)"** ที่แสดงในแต่ละผลลัพธ์เสมอ เพื่อความชัวร์ ถ้า field ไม่ตรง ให้ไปแก้ `WINNER_FIELD_CANDIDATES`/`PRICE_FIELD_CANDIDATES` ใน `egp_intelligence.py` ให้ตรงกับ response จริง
- กดปุ่ม "บันทึกเป็นคู่แข่ง + วิเคราะห์ด้วย AI" เพื่อส่งผลลัพธ์เข้าแท็บ "คู่แข่ง" ของโครงการที่เลือกได้ทันที

## วิธีใช้งาน

1. ไปที่หน้า **โปรไฟล์บริษัท** กรอกข้อมูลบริษัท (ประสบการณ์ ใบรับรอง ผลงาน ทีมงาน ศักยภาพการเงิน) — ยิ่งละเอียดยิ่งช่วยให้ AI ประเมินแม่นยำขึ้น
2. ไปที่หน้า **วิเคราะห์ TOR ใหม่** วางข้อความ TOR หรืออัปโหลดไฟล์ (PDF/DOCX/TXT) แล้วกด "เริ่มวิเคราะห์ด้วย AI" (รันครบ: TOR → ความเสี่ยง → โอกาสชนะงาน → เนื้อหาขาย)
3. ดูผลลัพธ์ในหน้า **โครงการทั้งหมด** — ระบบจะแสดงป้าย **Bid/No-Bid** เด่นชัดที่หัวหน้าโครงการก่อนแท็บทั้งหมด ให้ตัดสินใจก่อนลงแรงต่อ
4. ถ้าตัดสินใจเข้าประมูล ไปต่อที่แท็บ **BOM/ต้นทุน** (ร่าง solution + ราคา) และ **คู่แข่ง** (วิเคราะห์จุดข่ม) เพื่อเตรียมเล่มข้อเสนอ
5. เปลี่ยนสถานะโครงการตามความคืบหน้าจริง (ยื่นข้อเสนอแล้ว / ชนะงาน / ไม่ได้งาน)
6. เมื่อชนะงาน เปลี่ยนสถานะเป็น "ชนะงาน" แล้วไปที่:
   - หน้า **จัดซื้อ/RFQ** เพื่อสร้างใบขอราคาจาก BOM และเทียบใบเสนอราคา vendor
   - หน้า **ตรวจสัญญา** เพื่อ redline ร่างสัญญาและดึงข้อผูกมัด
   - หน้า **บริหารสัญญา** เพื่อแตก milestone และติดตามความคืบหน้า

## หมายเหตุ

- โมเดลเริ่มต้นคือ `claude-sonnet-5` เปลี่ยนได้ผ่านตัวแปร `TOR_AI_MODEL` ใน `.env`
- ค่าใช้จ่ายคือค่า API ของ Anthropic ตามการใช้งานจริง (pay-as-you-go) ไม่มีค่าใช้จ่ายอื่นเพิ่มเติม
- ข้อมูล TOR, ผลวิเคราะห์, ผู้ใช้ และ audit log เก็บในไฟล์ `data/tor_ai.db` (SQLite) — สำรอง/ย้ายข้อมูลได้โดยคัดลอกไฟล์นี้
- รหัสผ่านเก็บเป็น PBKDF2-SHA256 hash (200,000 รอบ) ไม่มีการเก็บ plaintext ที่ไหนเลย

### การ deploy ให้หลายคนใช้งานพร้อมกันจริง

Streamlit แยก `st.session_state` ต่อ browser session อยู่แล้ว จึงรองรับหลายคน login พร้อมกันได้ทันทีถ้า **deploy ขึ้นเซิร์ฟเวอร์กลาง** (ไม่ใช่รันบนเครื่อง local คนเดียว) เช่น Docker บน internal server หรือ cloud VM พร้อม HTTPS ข้อควรพิจารณาเพิ่มเติมสำหรับ production จริง:

- **SQLite เหมาะกับทีมเล็ก** (ผู้ใช้พร้อมกันไม่เกิน ~10-20 คน ใช้งานไม่ถี่มาก) เพราะการเขียนพร้อมกันจะถูกล็อกเรียงคิว ถ้าทีมใหญ่ขึ้นควรย้ายไป PostgreSQL (โครงสร้างตารางเดิมใช้ SQL มาตรฐาน ย้ายไม่ยาก)
- **SSO** — ถ้าองค์กรมี Google Workspace/Microsoft 365 อยู่แล้ว แนะนำเปลี่ยนจาก username/password มาใช้ `st.login()` (OIDC) แทน เพื่อไม่ต้องดูแลรหัสผ่านเอง
- **Row-level scoping ตามส่วนงานแบบเข้ม** — ตอนนี้ RBAC เป็นระดับ "หน้า" (page-level) ทุกคนใน role เดียวกันเห็นโครงการเดียวกันหมด ถ้าต้องการให้แต่ละส่วนงาน/แต่ละคนเห็นเฉพาะโครงการของตัวเอง ต้อง filter `db.list_projects()` ด้วย `department_id`/`created_by_user_id` ที่มีอยู่ในตาราง `projects` แล้ว (ยังไม่ได้บังคับใช้ในเวอร์ชันนี้)
